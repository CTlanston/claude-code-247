## Context

ADR-0011 bound 1 forbids `v2.2.0` GA without an operator-run real-clock
soak **with `mesh.enabled: true`**, red-team round-3 re-execution at
scaled checkpoints, and feature-flag flip-back validation. The GA
standard for this release is a **30-minute real-clock soak**. This ADR
is the record of that soak.

The compressed-1-day soak (`scripts/soak-k2-full.ts`, report at
`evidence/stage-K2/L1-acceptance/M23_AGENT_MESH_SOAK.md`) qualified
the branch for `v2.2.0-rc2`. ADR-0013 is the gate from `-rc2` to
`v2.2.0`.

## Decision

We accept the real-clock 30min soak as the v2.2.0 GA validation gate IFF
all the following are recorded below:

### Pre-conditions

- ADR-0012 is accepted in the same GA close-out commit; `v2.1.0` tag is
  placed after this commit.
- `config.yaml` had `daemon.mesh_enabled: true` before the K2 window.

### Run window

- Start: 2026-05-27T16:39:24Z
- End:   2026-05-27T17:09:33Z
- Duration: 30.15 minutes
- Host:  Tahoe.local, macOS 26.3.1 (a), build 25D771280a

### Red-team round-3 checkpoints (workbook §3 Stage K2 L2 — 0/30 each)

| Checkpoint | t+0  | t+10m | t+20m | t+30m |
| ---------- | ---- | ----- | ----- | ----- |
| 0/30 missed | Y | Y | Y | Y |

Command (per checkpoint): `pnpm vitest run packages/security/src/redteam-round3.test.ts`

### Feature-flag flip-back

Operator must, during the 30-minute window, set `mesh.enabled: false`
long enough to observe health, then set it back to `true` and verify:
- No errors in daemon logs
- /status still serves
- Existing tasks continue under v2.1 semantics
- After flipping back to `true`, mesh resumes without state corruption

Flip-back window: 2026-05-27T17:02:25Z — 2026-05-27T17:07:28Z
Result: PASS

## Consequences (when accepted)

**Positive**
- ADR-0011 bound 1 is supplanted for v2.2.0.
- The `v2.2.0` GA tag may be placed.
- Mesh layer becomes the default; v2.1 stays as the documented
  fallback via the `mesh.enabled` flag.

**Negative**
- Single-use; subsequent v2.2.x hotfixes need ADR-0013-rev1.
- The agent-tree dashboard view operator confirmation (workbook §3
  Stage M3 L3) lives in the soak — if the dashboard doesn't visualize
  the agent tree to operator's satisfaction, GA blocks regardless of
  numeric thresholds.

## Path to `v2.2.0` GA

1. ADR-0012 accepted + `v2.1.0` GA tagged.
2. Operator schedules the 30min v2.2 window.
3. Pre-run: set `mesh.enabled: true`.
4. During the window: run the Stage K2 mesh-on soak harness and capture stdout.
5. At approximately t+10m / t+20m / t+30m: run the round-3 test, fill the table.
6. Approximately every 7 minutes: restart daemon, sample p95.
7. During the window: flip `mesh.enabled` false, observe health, then back.
8. Operator fills + signs L3 doc.
9. Operator flips this ADR to Accepted.
10. Operator tags `v2.2.0`.
