# ADR-0009: Runtime emission must not dirty the tracked tree

**Status**: Accepted
**Date**: 2026-05-13 (Cycle 43)
**Applies to**: every disk emitter the system runs as part of a wake-cycle

## Context

The launchd-driven wake script (`scripts/autodev_continuous_cycle.sh`)
enforces an L7 §4 step 1 invariant on every wake: `git status
--porcelain` must be empty before the cycle proceeds. Otherwise the
wake writes `BLOCKED.md` and exits. This is intentional — a dirty
tree means some previous cycle (or an external process) left changes
that haven't been committed, and proceeding could squash them.

But many of the system's components emit artifacts to disk as part
of their normal runtime:

- `autodev/executors/claude_code_cli.py:_log()` writes to
  `reports/session-log.md` on every cli call
- `orchestrator/health.py` writes to `reports/health.json`,
  `reports/health.md`, and `reports/health.history.jsonl` on every
  invocation
- (Hypothetical future) lint runners write
  `reports/lint-results.json`
- (Hypothetical future) flake detectors write
  `reports/flake-history.jsonl`

If any of these emitters writes to a TRACKED file, every wake's
post-emission state contains a modified tracked file. The next
wake's `git status --porcelain` check fails. The launchd path
stalls within 1–2 wakes.

**FAIL-0009** is the canonical example. Pytest's cli-executor
unit tests called the real `_log()` writer against the real
`reports/session-log.md` path (a tracked file). Every pytest run
dirtied the tree. The misattribution sat in the ledger for ~30
cycles before Cycle 33's `cp / diff` reproducer correctly
identified the surface.

Across the four cycles 33 → 38 → 39 → 40, the system applied this
pattern in different ways to different surfaces. This ADR names
the pattern explicitly so future cycles facing similar surfaces
follow it deliberately rather than rediscovering it.

## Decision

**When a module or script emits an artifact to disk as part of
its normal runtime (logs, score snapshots, history files, status
reports), the emission MUST NOT cause `git status --porcelain` to
show that artifact as a modified tracked file.**

Three acceptable mechanisms, in **preference order**:

### 1. `.gitignore` + `git rm --cached` (preferred)

For artifacts that are unambiguously operational-only (per-run
snapshots, append-only trend logs, transient telemetry):

```gitignore
# Operational-only — regenerated by <writer> on every call;
# tracking would cause wake-script "git status clean" failures.
reports/health.json
reports/health.md
reports/health.history.jsonl
```

Then `git rm --cached <path>` to untrack any existing copies.
Files stay on disk for consumers.

**Example**: Cycle 39 applied this to the 3 health artifacts.

### 2. Env-var gate on the writer

For cases where the artifact IS legitimately tracked (real
audit-log history that operators read) BUT a specific context
(typically tests) must not append:

```python
def _log(self, event, r):
    if os.environ.get("AUTODEV_AUDIT_LOG_SUPPRESS"):
        return
    # ... normal write path
```

Then set the env var in `tests/conftest.py`:

```python
os.environ.setdefault("AUTODEV_AUDIT_LOG_SUPPRESS", "1")
```

Production callers don't set the var; the audit log keeps
accumulating normally.

**Example**: Cycle 33 applied this to
`autodev/executors/claude_code_cli.py:_log()`.

### 3. Read-only consumer pattern

For cases where a consumer (e.g. the doctor, a status command,
or an inspector) needs to READ the artifact but should NOT trigger
re-emission:

```bash
# In scripts/autodev_doctor.sh:
if [[ -f reports/health.json ]]; then
  # READ-ONLY: parse + display; do NOT call autodev_health.sh
  score=$(python3 -c "import json; ...")
fi
```

The emitter is invoked elsewhere (e.g. by the wake script before
its own read, or by the operator manually). The consumer only
reads.

**Example**: Cycle 38 applied this to `scripts/autodev_doctor.sh`'s
new health check.

## Alternatives considered

### A. Always emit to `state/` instead of `reports/`

`state/` is already mostly gitignored (`state/*.db`,
`state/PAUSED`, etc.). Moving runtime artifacts there would
sidestep the issue.

**Rejected**: `reports/` is the canonical location for operator-
readable telemetry per the existing repo conventions. Splitting
artifacts across two directories purely for git-tracking reasons
would surprise operators and conflict with the master prompt's
§17 ("`reports/` files are the system's external interface").

### B. Wake script does `git stash` + `git stash pop` around emission

The wake could stash any pending changes, emit, then unstash.

**Rejected**: Stashing is a destructive-ish operation that
violates §0 rule 4 ("never run destructive git ops without a
tagged restore point"). Stash collisions with real work-in-progress
would cause subtle data loss.

### C. Tolerate dirty trees in the wake script

Skip the `git status clean` check entirely. Let emitter writes
accumulate as "phantom" dirty state that the cycle ignores.

**Rejected**: The dirty-tree check exists to protect REAL
uncommitted work. Disabling it would silently let real
incomplete cycles get clobbered by subsequent wakes. The
invariant is load-bearing.

## Consequences

### Positive

- The wake script's `git status clean` invariant stays intact and
  meaningful.
- Cycles that introduce new emitters know exactly what pattern to
  follow.
- The 3 mechanism options cover every real surface — they're not
  arbitrary, they're each driven by a specific concern:
  preference 1 = "operational only", 2 = "tracked but tests
  shouldn't add", 3 = "consumer shouldn't trigger emission".

### Negative

- Adds a small mental tax: every new emitter prompts the
  question "which of the 3 mechanisms?". Without this ADR the
  question was implicit and easy to miss.

### Neutral

- `state/` and `reports/` continue to coexist as distinct
  destinations with their own gitignore patterns. This ADR
  doesn't reorganize directories.

## Verification

Each applying cycle (33, 38, 39, 40) added a regression test
that fails LOUDLY if a future change re-introduces the
dirty-tree side effect:

- `tests/test_doctor_no_side_effect.py` (Cycle 33, 4 tests)
- `tests/test_doctor_health_check.py` (Cycle 38, 3 FAIL-0009
  regression guards)
- `tests/test_health_gitignored.py` (Cycle 39, the gitignored-
  paths assertion)
- `tests/test_wake_refreshes_health.py` (Cycle 40, end-to-end
  invariant guard)

Adopting this ADR is therefore not just documentation — it's
backed by 12 specific regression tests across 4 surfaces.
