# ADR-0016: v2.3 Mission OS Incremental Autonomy

**Status:** Accepted
**Date:** 2026-05-28
**Builds on:** [ADR-0010](0010-three-plane-event-sourced.md)

## Context

The v2.1/v2.2 line established the local-first, event-sourced, three-plane
foundation. The next product step is not a clean-room rewrite; it is a
practical Mission OS layer that keeps the local daemon and adds:

- a Claude Code + Codex CLI subscription worker pool,
- brainstorm-to-PRD/ADR/task-DAG mission design,
- bounded move execution for long-running work,
- evidence-only reviewer/validator isolation,
- draft-PR creation without automatic merge.

## Decision

v2.3 is an incremental extension of the existing `@aedev/*` packages.

1. Add Codex CLI as a first-class local subscription worker alongside Claude
   Code. No silent API fallback is introduced.
2. Route work by role through a worker-pool router, with dynamic concurrency
   bounded to 1-5 healthy local sessions.
3. Represent mission design as structured PRD, ADR draft, roadmap, task DAG,
   and checkpoint data that can be validated before execution.
4. Treat validators as evidence-only consumers. Validator inputs are redacted
   by construction and exclude coder transcript, model name, retry count, and
   token/cost data.
5. Permit daemon-only branch push and draft PR creation behind the existing
   remote-write and push-policy gates. v2.3 never auto-merges.

## Consequences

The system becomes useful as a 7x24 local coding coworker without adding
Postgres, Redis, Daytona, or OpenHands as required dependencies. Those remain
optional future worker backends.

The cost of this choice is that v2.3 remains single-host and bounded by local
subscription session availability. High throughput is achieved through many
small recoverable moves, not through a single unbounded model session.
