# ADR-0017: V2.4 Vertical Slice and Dual-Family Validation

**Status:** Superseded by WORKBOOK_v3 P1
**Date:** 2026-05-29
**Builds on:** [ADR-0010](0010-three-plane-event-sourced.md), [ADR-0016](0016-v2.3-mission-os.md)

## Context

V2.3 made the Operator Cockpit and Mission OS visible, but the next proof
cannot be another synthetic soak.  The operator selected a real first target:
`CTlanston/multi-agent-brainstorm`, a private Node-based repo whose working
checkout must not be damaged.

The product goal is high-quality PR throughput.  Token count and runtime are
diagnostic signals, not the north star.  The build order is therefore a
vertical slice first: one real mission through the whole local path, then
horizontal hardening.

## Decision

V2.4 uses model C:

1. The TypeScript daemon owns durable state, safety gates, objective
   validation, forbidden-path scanning, evidence, and landing policy.
2. A mission worker owns creative PLAN -> IMPLEMENT -> self-review inside a
   per-task worktree.
3. Any mission claiming a dual-validation hard gate must be authored by local
   Claude (`anthropic`) so Gemini (`google`) and OpenAI (`openai`) are both
   independent validator families.
4. A Codex-authored mission can still run, but it cannot claim two independent
   validator verdicts when OpenAI is one of the validators.  It degrades to
   objective gates plus the independent validator families that remain.
5. The first real run stops at local branch, local commit, and evidence.  It
   does not push, open a PR, merge, or fake a soak.

## Consequences

The first V2.4 evidence may be ugly: session holds, quota problems, missing
Gemini keys, validation failures, or audit failures are all valid results.
They must be recorded honestly as evidence and HOLDs, not papered over.

Draft PR creation remains a later gated phase and still requires explicit
remote-write permission, an enabled repo, and operator approval.  Auto-merge
is out of scope for V2.4.

## Validation

- In WORKBOOK_v3 P1, `WorkerPoolRouter` routes planner work to `claude-cli`
  and coder work to `codex-cli`; dual-validator independence is enforced by
  merge policy rather than by switching the coder family.
- Merge policy must require two validator families independent of the coder
  family when the hard gate is active.
- The V2.4 S0 harness must clone `CTlanston/multi-agent-brainstorm` into a
  safe copy with spaces in the path, run a local Claude worker in a per-task
  clone, rerun objective gates, scan forbidden paths, create only a local
  commit, and write evidence.
