## Why this matters for launchd

Before this cycle: if a future cycle has the wake script call
`autodev_health.sh` to refresh the score, every wake would
generate 3 changes:
- `M reports/health.json`        (timestamp + score)
- `M reports/health.md`          (timestamp + signal table)
- `M reports/health.history.jsonl` (one appended line)

These would all appear in `git status --porcelain`. The wake
script's `if [[ -n "$(git status --porcelain)" ]]; then exit 0 (skip cycle)`
guard (or its analog in the prompt) would trigger, and the
launchd path would stall after the first dispatch attempt.

After this cycle: the files exist on disk for consumers but
git treats them as transparent. The wake script can refresh
health on every wake without dirtying the tree.

This is the SAME class of fix as Cycle 33's
AUTODEV_AUDIT_LOG_SUPPRESS env-var gate, just applied to a
different surface — the discipline rule "don't track
regenerated artifacts" is well-encoded now (5 such files
gitignored: heartbeat, codex-reviews, adversarial-reviews, +
this cycle's 3).

## Discipline pattern emerging

Across this resumed session, a coherent pattern: every
launchd-path safety fix has followed the same shape:

1. Identify the surface that emits state on each call.
2. Make that emission not appear in `git status --porcelain`,

3. Add a regression test that fails LOUDLY if a future cycle
   re-introduces the dirty-tree side-effect.

Three cycles, one principle, three independent surfaces — the
launchd path's "git status clean" invariant is now genuinely
robust.
