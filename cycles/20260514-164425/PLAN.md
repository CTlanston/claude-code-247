# Cycle 20260514-164425 PLAN — Cycle β (launchd auth fix)

## Target dimension
**S — Safety gates** (closes the "launchd-spawned `claude` reports `Not
logged in`" hole that makes 24/7 continuous mode silently no-op every
wake; codifies a §0-compliant single-line `.env` reader so secret access
stays auditable).

Secondary dim moved by side-effect: **E — Self-improvement** (ADR-0010
documents the keychain-vs-launchd ACL constraint, which Planner can cite
in future cycles).

## Specific gap being closed
Out-of-band PlistBuddy + Cursor edits to
`~/Library/LaunchAgents/com.lanston.autodev.continuous.plist`
(PATH-extended, HOME=`/Users/lanston`) are NOT reproduced by
`scripts/install_launchd_continuous.sh`. Any reinstall today regresses
back to a non-working plist. Even with the patches, the live plist
hits keychain ACL because macOS denies launchd-spawned children access
to the Terminal-scoped keychain entry storing Claude's OAuth token →
`claude` reports `Please run /login`. Per §3 Track S, this is a missing
gate: the install pipeline doesn't guarantee a runnable plist.

## Change being made
Two-file behavior change (smallest vertical slice):

1. `scripts/install_launchd_continuous.sh` — auto-discover the
   directory containing `claude` at install time (`command -v claude`
   with `mdfind` fallback), prepend it to the plist's `PATH`, embed
   `HOME` as an absolute path, warn at install time if discovered
   path is under `~/.npm/_npx/` (unstable cache).
2. `scripts/autodev_continuous_cycle.sh` — between timeout-binary
   resolution and `claude -p` dispatch, grep exactly one
   `^ANTHROPIC_API_KEY=` line from `$REPO/.env`, route by token prefix
   to `CLAUDE_CODE_OAUTH_TOKEN` (oat01) or `ANTHROPIC_API_KEY`
   (api03). Never `eval`, never echo, never cat. Variable unset after
   export.

Plus ADR-0010 documenting the keychain-vs-env decision.
